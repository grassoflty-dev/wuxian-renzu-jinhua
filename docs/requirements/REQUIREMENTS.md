# 游戏要求总入口

版本：R1-DRAFT；整理日期：2026-10-06（JST）。范围：公开游戏设计摘要与原方案索引。

本文件方便新接手者理解游戏目标，不是执行任务队列、电脑操作授权或实现完成证明。完整细则仍须读取 [REFERENCE_INDEX.md](REFERENCE_INDEX.md) 中的原方案。本文尚待补入本地 Codex「游戏本体」对话摘要及主策划近期完整变更，不能宣称已经收齐全部历史要求。

## 阅读顺序与冲突处理

1. 先读本文中的「最新覆盖」和待补证条目
2. 再按参考索引读三世界总方案、视觉方案、UI 方案、玩法工程规格、工程补充、雾港冻结稿
3. 最新明确用户决定覆盖相同范围的旧条款；主策划的后续明确裁决只覆盖其指明范围，不能扩散到其他世界/玩法
4. 来源未读全、内容有冲突时保留双方与待核状态，不能凭实现方便选一个
5. 文档中的建议、示例、目标、历史实现状态不等于用户已经逐项批准，也不等于当前版本已实现

状态：U=用户明确要求；P=已保存策划规范；P*=后续策划决议有归档但完整对话仍待汇总；O=细节待核；F=未来扩展。实现状态单独由固定提交及对应测试证据说明，本清单不授予 PASS。

## 产品与 V1 范围

- G-001 [P] 固定斜视角 2.5D、多世界、长期扩展的无限流 Action RPG。成长核心是突破普通人的感知、身体、信息、移动、认知与规则限制，不是单纯数值升级 [S1/S4]
- G-002 [P] V1 是连续战役：归航站 → 灰巢 → 归航站/能力选择 → 雾港 → 归航站 → 钟骨 → 尾声/有限重访；不扩第四个首发世界 [S1/S4 §3、19、41]
- G-003 [P] 新世界应带来新的人类限制，已有构筑能提供不同解法，奖励能跨世界产生价值 [S4 §2、37–40、48]
- G-004 [U] 主要交付 Windows 游戏。没有对应源码/构建的实机证据，不能说 Windows 已通过；自动化、局部检查、启动、完整试玩分别记录

## 感知、地图、技能

- G-010 [U/O] 鼠标滚轮查看更大地图时，普通人不能因缩放获得超出原本感知范围的信息；不可知远处保持黑暗/不可辨认。技能/道具可扩展可知范围，范围随强度变化。近处应保持可读，远处压缩更多。用户随后明确原先称为「临时方案」的方式就是其本意；该澄清所指的具体方案全文尚需补入，禁止擅自认定必须采用某种非线性投影公式
- G-011 [U] 附近地图可以保持显示；身后敌人、非本势力人物/怪物默认不显示，可通过声音提供线索；特定能力允许后视。地形记忆、实时实体感知、声音信息必须分开
- G-012 [U/P] 能力设计采用可组合的原创机制，例如爬墙、危险感应、钩索、力量增强。不能因为拆分机制就宣称第三方角色名称、造型、故事等已获使用许可；旧 IP 指向内容不自动进入公开内容集 [S4 §21]
- G-013 [P] 地图知识按 Topology/Terrain/Connections/Objectives/Enemies/Hazards/Loot/NPCs/Secrets 分通道；全地形地图不自动暴露敌人/秘密。真实 explored 历史与显示权限分离 [S4 §9]
- G-014 [P] 无地图能力也记录真实探索，获得后可显示过去走过的区域；远程扫描不能伪造永久探索。声学映射提供授权方向/距离/短时轮廓，不等于永久全图和精确敌人血量 [S4 §12.6、14、36；S6]
- G-015 [P] 未获 Local Map 不显示玩法小地图；未获 Enemy Vitals 不显示敌人 HP，初级只显示定性生命状态；Rear View 随能力取得。无障碍设置永远不能被能力门控 [S2/S3/S4]
- G-016 [P/F] 道具、装备、技能、血统、能力、Buff、世界效果统一进入 EffectSource → Resolver → EffectivePlayerRules。不同来源可组合；移除一个来源不必然移除效果；不为每种道具写场景特判。V1 不必实现所有高阶能力 [S4 §8、20–28；S5]

## 操作、战斗与存档

- G-020 [P] WASD 屏幕直觉移动，鼠标瞄准，左键/J 普攻，Shift Dash，Q Pulse，E Guard，R Pierce，F 交互，Space 情境跨越，T 终端，M 受权限限制的地图，Esc 暂停。固定视角，不做右键自由旋转 [S4 §5]
- G-021 [P] 普攻有前摇/生效/恢复；Dash 启动锁方向、Rust/KCC 决定碰撞且不是瞬移；Pulse 径向扫描/作用，Guard 前方弧盾，Pierce 线性穿透，四者动作轮廓不能仅靠换色区别 [S3/S4 §6]
- G-022 [P/F] V1 保留 Q/E/R 默认映射，内部预留可换主动技能槽；未来飞行/相位不能绕过世界边界或剧情封印 [S4 §10、18、24]
- G-023 [P] 保存真实强化来源与世界状态，载入后重新解析规则；不把派生 EffectivePlayerRules 当独立真值。重访保留世界改变、探索等状态，核心首通奖励不可重复刷取 [S4 §31–33]
- G-024 [P] 存档/重启/继续必须跨进程验证。一个坏档不应使其他正常存档失效；存档 UI 显示可读世界名称、时间、进度等 [S3 §78；S4 §44]

## 三世界和归航站

- G-030 [P] 归航站是小型技术中继站，V1 一个紧凑核心室，提供世界门、任务、能力、保存休息、储物等功能；解锁和重访由权威世界进度控制 [S4 §4]
- G-031 [P] 灰巢 11 场景连续路线、主电/封锁/撤离事件、Sentinel 双足重型设施守卫、便携信标；白芷为可选分支，不锁 Gate B 主线。首返 Local Map/Rear View/Regeneration 三选一；Scanner 提供初级定性 Enemy Vitals [S4 §11]
- G-032 [P] 雾港 9 场景连续路线，以雾、声音、信号、水域体现感知限制；声学映射提供优势，但 Warden 不应成为唯一能力硬钥匙检查 [S4 §12–14]
- G-033 [P] 雾港沿用 24×16m 几何与现有碰撞/交互位置；泵站 READY → DRAINING(6000ms) → DRAINED，按 F 一次启动，不因受击取消、不重复奖励。只改变指定两处水域；排水前普通角色受阻/减速，合法未来能力可绕行；泵不是世界完成事件，V1 不做泵站捷径。状态跨场景/存读/返站/重访保留，新旅程重置 [S6；S4 §13]
- G-034 [P] 钟骨是热、压力、蒸汽、运输和垂直机械工厂，不是天空钟表城市；三阀门、传送带、热/冷却、升降和 Boss 形成 9 场景闭环。获得 Air Step 前主路不得要求该能力 [S4 §15–18]
- G-035 [P/F] V1 Air Step 仅在 authored traversal 上，由 Rust 验证能力、起终点和冷却；不等于无限跳跃。后续可扩自由踏空/飞行 [S4 §18]
- G-036 [P] 历史方案复访上限：灰巢 2、雾港 2、钟骨 4；任何后续修改需明确记录覆盖，不能把该历史数值当已核实当前代码 [S4 §33]

## 美术、UI 与最新归航站覆盖

- G-040 [U/P] 实际地图/UI 应对齐已确认效果方向，不能以逻辑通过替代视觉验收。固定斜视角、高精度电影感 2.5D、工业战术终端 UI；不是纯平铺 Tile 或整屏概念图充当运行界面 [S2/S3]
- G-041 [P] HTML/CSS/TypeScript 实现屏幕 UI；Pixi 实现场景、角色、世界标记、特效、遮挡。共用核心 UI 信息架构，世界只换主题皮肤；科技青/目标暖金/危险红语义稳定 [S2/S3]
- G-042 [P] 岑遥：成熟亚洲女性、短黑发、炭灰短外套、青灰内层、单侧暗金结构、胸前金色菱形、深色工装裤和工业靴；早期克制普通人感。8 方向，步行应抬脚、重心/手臂运动，不靠滑行代替 [S3 §21–41、95]
- G-043 [P] HUD 克制：左上人物/HP/Energy、右上当前目标、下方技能、就近 F 提示；背包/日志等不常驻展开；不能泄漏内部 scene/action 标识。画面分层、脚底锚点、阴影/前景遮挡需与玩法位置一致 [S2/S3]
- G-044 [P*] 归航站物理核心室以环形门、工业支撑/管线形成焦点；蓝色球体是抽象世界网络 UI，不与物理房间合并。概念图不是整房背景替换许可。该条来自 2026-10-06 主策划后续归档，待完整对话补齐索引
- G-045 [P*] 2026-10-06 ROOM-FIT 仅适用于 return_station/rs_core_room：每个视口固定全室构图，无跟随/瞄准前移/死区/Boss 倍率/额外缩放；退出恢复原相机，重进/resize 重算。包含房间角点、环门/支撑/管线 XYZ、五终端真实视觉范围、已准入角色帧与形变范围。实际逻辑视口四边 5% 留白；输入使用同一已提交相机帧。不能改世界米制、碰撞、导航、交互距离、存档来迁就画面
- G-046 [P*] ROOM-FIT 场景取消固定角色像素高度硬指标，不放大角色补偿。5% 只证明视口内包含，不能证明 HUD 不遮挡或主观可读性。旧通用跟随相机条款在该场景被覆盖，在其他场景不自动失效
- G-047 [U] 优先工程，缺美术可用占位并明确记录。只有占位无法替代且确实阻塞代码才主动询问。概念/占位/最终资产须区分，素材权利与正式准入不能仅凭画面相似推定
