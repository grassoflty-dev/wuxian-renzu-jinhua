# 开发与上传规则

公开仓库以 `main` 为长期主线，tag 仅用于实际游戏版本发布。

## 每项变更的收尾

- 每项完整、可说明的源码变更结束后，立即提交并上传，不等待下一次定时检查或整款游戏完工。
- 仅做与变更有关的必要检查；源码上传不等于试玩通过或版本发布，未运行项目如实标注。
- 上传保持工程原目录；旧方案、废弃代码可以保留，不为公开库另造一套目录。
- 不上传凭据、私人协调记录、真实存档和缓存；素材需要具备再分发权。素材版权阻塞不应阻塞可独立上传的源码。
- 并行任务的提交与集成串行处理，保留他人的未提交修改。不要上传尚在写入的半成品或覆盖其他任务成果。

## 测试分支的收尾

- 可以为需要隔离的开发或测试创建短期分支，不为每次检查创建分支。
- 必要测试完成后，将有效变更合入 `main` 并确认远端上传成功。
- 确认分支没有独有的未保存成果、未提交修改、运行中的任务或仍使用它的工作区后，删除远端及本地测试分支。
- 未合并、尚在使用或仍有待处理结果的分支不直接删除；失败任务保留真实结果，不伪装为已合并。
- 不用备份 tag 代替分支清理；已合并代码通过正常提交历史恢复。
- 不强制推送、不重写主线历史、不批量删除仍在使用的工作区。
